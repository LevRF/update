# Безопасность

## От чего защищено

| Угроза | Защита |
|---|---|
| Взлом аккаунта GitHub или репозитория, подмена файлов в релизе | Подпись RSA-3072 закрытым ключом, который хранится только на компьютере владельца. Клиенты проверяют её встроенным открытым ключом |
| Подмена `manifest.json` | В подписи зашиты проект, версия, имя и SHA-256 файла: чужой или старый файл под видом новой версии не пройдёт |
| Откат на старую версию | Клиент не ставит версию ниже установленной |
| Битый или недокачанный файл | Проверка SHA-256; файлы ставятся, только если проверку прошли **все** файлы релиза |
| Файлы с чужих сайтов | Клиент качает только с `https://github.com/LevRF/update/releases/download/` и только по HTTPS |
| Архив с путями `../` и имена файлов с путями | Отклоняются |
| Вредоносный код в GitHub Actions | Workflow без сторонних actions, не запускается от pull request'ов, права токена — только запись в репозиторий |

## Ключ подписи — главное

- Закрытый ключ: `%USERPROFILE%\.update-signing\private-key.xml`. Отпечаток открытого ключа: `979599501415EEA4`.
- **Сделайте резервную копию** этого файла (зашифрованная флешка, менеджер паролей). Если ключ потеряется,
  придётся создать новый (`tools\New-SigningKey.ps1 -Force`) и заново раздать клиенты во все программы.
- **Никому не передавайте и не кладите в репозиторий, облако, мессенджеры.** Кто владеет этим файлом, может
  выпустить «обновление» для всех ваших программ. `.gitignore` блокирует `*.xml`, `*.pem`, `*.key`.
- Если ключ утёк: создайте новый, выпустите клиенты с новым открытым ключом, старые релизы удалите.

## Обязательные настройки (сделать один раз руками)

### Аккаунт GitHub
1. **Двухфакторная аутентификация**: Settings → Password and authentication → *Enable two-factor authentication*
   (приложение-аутентификатор или ключ безопасности, не SMS).
2. Токены для `Publish-Release.ps1` — только **fine-grained**, только репозиторий `LevRF/update`,
   право `Contents: Read and write`, срок действия ограничен (например 90 дней). Не сохраняйте токен в файлах.

### Репозиторий → Settings
3. **Rules → Rulesets → New branch ruleset**: цель — ветка по умолчанию (`main`),
   включить *Restrict deletions* и *Block force pushes*.
4. **Rules → Rulesets → New tag ruleset**: цель — все теги (`*`),
   включить *Restrict deletions*, *Restrict updates* и *Block force pushes* — опубликованные версии нельзя будет подменить.
5. **Actions → General**:
   - *Fork pull request workflows from outside collaborators* → **Require approval for all external contributors**;
   - *Workflow permissions* → **Read repository contents and packages permissions**
     (нужные права workflow запрашивает сам);
   - снять галочку *Allow GitHub Actions to create and approve pull requests*.
6. **Security → Advanced Security** (раньше *Code security*): включить **Secret scanning** и **Push protection** —
   GitHub не даст случайно запушить токен или ключ.
7. **General → Features**: можно отключить ненужные *Wiki* и *Projects*.

## Если вы пишете свой клиент

Проверка подписи обязательна. Формат подписанного сообщения (UTF-8, перевод строки `\n`):

```
update-sig-v1
<проект в нижнем регистре>
<версия>
<имя файла>
<sha256 файла, hex в нижнем регистре>
```

Подпись — RSASSA-PKCS1-v1_5 с SHA-256, в манифесте в поле `signature` (base64).
Открытый ключ — константы `PUBLIC_KEY_N` / `PUBLIC_KEY_E` в `client/updater.py`.
Открытый ключ должен быть встроен в программу, а не скачиваться из репозитория.
